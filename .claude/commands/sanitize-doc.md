Методика й обґрунтування: `docs/sanitization-checklist.md`.
Приклад результату: `docs/sanitized-brief.md`.

## Роль

Інженер, який готує клієнтський матеріал до роботи з AI. Твоя задача —
**зменшити радіус ураження, не втративши задачу**.

## Мета

Прочитати `$ARGUMENTS`, класифікувати вміст за світлофором і видати
санітизовану версію, придатну для роботи з моделлю.

## Контекст

Прочитай **перед роботою**:

- `$ARGUMENTS` — вихідний документ;
- `docs/sanitization-checklist.md` — класифікація (§1), патерни пошуку (§2),
  техніки маскування (§3), режим для креденшелів (§4).

### Що тут означає «локально» — точно

Формулювання «оригінал у модель не потрапляє» саме по собі було б самообманом:
цю команду виконує агент, а агент **і є** модель — усе, що він прочитає,
опиниться в його контексті. Тому правило формулюється за категорією документа.

**Крок 0 (до читання вмісту): визнач категорію й скажи вголос, у якому режимі
працюєш.** Якщо категорія неясна — вважай 🔴.

| Категорія | Режим роботи |
|---|---|
| 🔴 є секрети, PII або продакшн-вигрузка | Агент оригінал **не читає**. Спершу детермінований локальний прохід (скрипт `sed`/`python` під контролем людини) створює `<файл>-sanitized`; у контекст іде **лише** він |
| 🟡 внутрішня логіка й комерція, без секретів і PII | Агент може читати оригінал, **якщо** сесія на тирі, дозволеному для 🟡 за `docs/sanitization-checklist.md` §5 (enterprise / no-train). На споживчому тирі — ні |
| 🟢 лише постановка задачі | Читання без обмежень |

**У публічну модель оригінал не потрапляє ніколи** — ні цілком, ні частинами,
ні «щоб вона допомогла замаскувати»: модель, яку просять замаскувати секрет,
спершу його прочитала.

## Обмеження

- **Не редагуй оригінал.** Результат — новий файл поруч, суфікс `-sanitized`.
- Не вигадуй фактів, яких у документі немає, заповнюючи пропуски.
- Не маскуй постановку задачі, критерії приймання й обсяги — це 🟢.
- **НЕ виводь сирі збіги з оригіналу.** `rg -n` друкує рядок цілком — разом із
  ключем, email чи connection string, який ти щойно знайшов. Це переносить
  секрет із файлу у відповідь, у транскрипт сесії й далі в історію. По
  **оригіналу** звітуй лише метаданими:

  ```bash
  # МОЖНА: патерн, номер рядка, категорія — без вмісту
  rg -n --only-matching --replace '<REDACTED>' '<патерн>' "$FILE"
  rg -c '<патерн>' "$FILE"          # лише кількість збігів
  rg -n --no-heading '<патерн>' "$FILE" | cut -c1-12   # тільки «файл:рядок:»
  ```

  Повний рядок можна показувати **тільки з результату** (`-sanitized`), де
  значень уже немає.
- Не фільтруй вивід пошукових патернів (`| rg -v ...`): шум читається очима.
  Але перед довірою до порожнього виводу зроби контрольний прогін із
  `docs/sanitization-checklist.md` §2 — порожньо часто означає «не сканувалось».
- Плейсхолдери **стабільні**: одна сутність = один ідентифікатор по всьому
  документу (`[CLIENT_1]`, `[CONTACT_1]`, `S1..S5`).

## Acceptance criteria

- [ ] Названо категорію документа (🔴/🟡/🟢) і режим роботи за таблицею вище —
      **до** того, як прочитано вміст.
- [ ] Прогнано всі патерни §2 чек-ліста по **оригіналу**; звіт містить лише
      `патерн | файл:рядок | категорія | замаскований фрагмент` — **жодного
      сирого рядка з оригіналу**.
- [ ] Зроблено контрольний прогін (`files searched` збігається з очікуваним):
      порожній вивід без нього не вважається доказом.
- [ ] Кожну знахідку класифіковано 🔴/🟡/🟢 і застосовано техніку з §3.
- [ ] Креденшели — `<SECRET_OUT_OF_BAND>`; **жодного значення** в результаті.
- [ ] Вигрузки замінені синтетикою того самого формату, зі збереженням
      крайових випадків (юрособа, відсутнє поле, нестандартна адреса).
- [ ] Ті самі патерни прогнано по **результату**; усе, що підсвітилось,
      пояснено (синтетика — очікувано, справжнє значення — ні).
- [ ] Звірено, що в результаті немає **дослівних** рядків з оригіналу
      (окрім 🟢-постановки).
- [ ] Є таблиця «що прибрано → категорія → чому задача не постраждала».
- [ ] Названо підсумковий тир документа (🟢/🟡) і який інструмент йому
      відповідає за §5.

## Формат відповіді

1. Вивід патернів по оригіналу.
2. Таблиця класифікації знахідок.
3. Готовий санітизований файл.
4. Вивід патернів по результату + пояснення кожного збігу.
5. Таблиця «що прибрано і чому задача вижила».
6. Підсумковий тир документа.

## Stop

Зупинись після санітизованого файлу й перевірки. **Не надсилай нічого нікуди**
і не починай виконувати саму задачу з брифу — це окремий запит.
