# Документація модуля

## Роль

Технічний письменник із досвідом розробки. Ти пишеш для інженера, який щойно
прийшов у проєкт: він **не читатиме реалізацію**, він читатиме твій документ і
одразу піде писати код.

## Мета

Описати публічний API модуля так, щоб його можна було коректно використати без
відкривання вихідного файлу — включно з межами застосовності й підводними
каменями.

## Контекст

Прочитай **перед роботою**:

- `app/src/quote.ts` — модуль, що документується (єдине джерело правди про API);
- `app/src/quote.test.ts` — тести; вони показують **реальну** поведінку на межах,
  зокрема яких входів функції не приймають;
- `app/package.json` — назва пакета, команди.

Домен: розрахунок кошторисів на автоматизацію. Усі суми — **цілі числа в
центах**; це головне, чого не знає новачок і на чому він помилиться першим.

Вихідний файл: `app/README.md`.

## Обмеження

- Документуй **лише те, що є в коді**. Не вигадуй параметрів, опцій і функцій
  «які логічно було б мати».
- НЕ змінюй код заради документації. Якщо API незручний — напиши це окремим
  абзацом «Відомі обмеження», але код не чіпай.
- Без маркетингу й води: жодних «потужний», «легко і просто», «сучасний».
- Приклади — тільки такі, які реально запускаються на поточному API.

## Acceptance criteria

- [ ] Описано **всі** експортовані сутності з `quote.ts`, жодної зайвої.
- [ ] Для кожної функції: призначення, параметри з одиницями виміру, що повертає,
      і за яких входів **кидає помилку**.
- [ ] Є мінімум один приклад «від входу до відформатованого результату»,
      з очікуваним виводом у коментарі.
- [ ] Явно названо інваріант центів (сума частин = вихідна сума) і правило
      «усі суми — цілі в центах».
- [ ] Кожен приклад скопійовано в тимчасовий файл і виконано; результат збігся
      з тим, що написано в коментарі.
- [ ] Є розділ «Відомі обмеження» з тим, чого модуль **не** робить.

## Формат відповіді

Готовий `app/README.md` у markdown: короткий вступ (≤3 речення) → таблиця API →
приклад → інваріанти → відомі обмеження. Без розділу «Вступ до TypeScript».

## Stop

Після README зупинись. Не пиши JSDoc у код, не додавай CHANGELOG, не заводь
docs-сайт — це окремі задачі.

## Результат запуску

**Коли:** 2026-09-14 · **Вхід:** `app/src/quote.ts` (уже виправлений) ·
**Вихід:** [`app/README.md`](../app/README.md)

Що дав промпт:

- README на 60 рядків, усі 4 експорти (`QuoteInput`, `estimateTotalCents`,
  `splitInstallments`, `formatMoney`), жодного вигаданого.
- Критерій «за яких входів **кидає помилку**» виявився найкориснішим: він
  змусив піти в код і виписати обидва `RangeError` із точними межами. Без нього
  вийшов би переказ сигнатур — те, що й так видно з типів.

**Критерій, який зловив реальну помилку в моєму ж тексті.** Рядок «кожен
приклад скопійовано в тимчасовий файл і виконано» — не формальність. Перший
варіант прикладу мав показати головний інваріант (остача не зникає) і був
такий: `estimateTotalCents({ hours: 60, rateCents: 4500 })` → розбити на 3.

Прогін (`node` з нативним стрипом типів, Node 24) показав, що приклад
**демонструє не те**: 60 × 4500 = 270000, а 270000 ділиться на 3 націло →
`[90000, 90000, 90000]`, три однакові `"$900.00"`. Тобто приклад, написаний
саме щоб проілюструвати розподіл остачі, не містив жодної остачі. Очима це не
видно — видно тільки запуском.

Замінив на `{ hours: 20, rateCents: 5000 }` → 100000, і отримав із реального
прогону:

```
total          = 100000 → $1,000.00
parts          = [33334,33333,33333]
sum(parts)     = 100000
formatted      = ["$333.34","$333.33","$333.33"]
parts=0        → RangeError: parts має бути цілим числом ≥ 1, отримано 0
discount=150   → RangeError: discountPercent має бути в межах 0..100, отримано 150
```

Саме ці рядки й лежать у `app/README.md` — включно з текстами помилок, які
інакше довелося б переказувати з пам'яті.

**Висновок:** «приклад має бути виконаний» — обов'язковий критерій для будь-якого
промпта на документацію. Приклад у README, який ніхто не запускав, старіє
швидше за код і дезінформує впевненіше.

**Обмеження спрацювало:** «документуй лише те, що є в коді» зупинило спокусу
описати `currency` як параметр `formatMoney` — його немає, валюта захардкожена
в `$`. Замість вигаданого параметра це пішло в «Відомі обмеження».
