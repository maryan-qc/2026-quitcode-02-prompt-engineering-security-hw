# Рефакторинг без зміни поведінки

## Роль

Інженер, що працює в legacy-коді, за який відповідає головою. Твоя одиниця
цінності — **читабельність при незмінній поведінці**, а не кількість
переписаних рядків.

## Мета

Зробити вказаний фрагмент зрозумілішим, довівши тестами, що зовнішня поведінка
не змінилась ні на йоту.

## Контекст

Прочитай **перед роботою**:

- `app/src/quote.ts` — файл для рефакторингу;
- `app/src/quote.test.ts` — тести; це **контракт**, який має лишитись зеленим
  без жодної правки;
- `app/README.md` — задокументована поведінка, включно з **текстами помилок**:
  якщо зміниш текст `RangeError`, README стане брехнею.

Домен: кошториси, суми — цілі числа в центах.

Команди: `cd app && npm test`, `cd app && npm run typecheck`.

## Обмеження

- **Один рефакторинг за раз.** Якщо бачиш три місця — назви три, зроби одне,
  решту випиши списком «на потім».
- **Заборонено правити `*.test.ts`.** Тест, який довелося підправити, означає,
  що поведінка змінилась — тобто це вже не рефакторинг.
- НЕ змінюй публічні сигнатури, імена експортів і тексти повідомлень помилок.
- НЕ додавай залежностей і нових абстракцій «на виріст» (інтерфейси, фабрики,
  шари під одну реалізацію).
- Продуктивність — не привід: цей код не в гарячому шляху.

## Acceptance criteria

- [ ] `cd app && npm test` зелений **до** зміни — зафіксовано вивід.
- [ ] `cd app && npm test` зелений **після** зміни, та сама кількість тестів.
- [ ] Файл тестів не змінювався **цим рефакторингом** — підтверджено дифом,
      узятим від стану *безпосередньо перед* зміною (`git stash`/коміт-чекпойнт
      або `git diff <sha-до-рефакторингу> -- app/src/`), а не голим
      `git diff --name-only` проти бази гілки.
- [ ] `cd app && npm run typecheck` без помилок.
- [ ] Названо, що саме стало зрозумілішим — конкретно, а не «чистіше».
- [ ] Перевірено на 3 входах вручну (звичайний, межовий, від'ємний), що
      результат **побайтово** той самий, що й до зміни.
- [ ] Список «не чіпав, але варто» — з причиною, чому не зараз.

## Формат відповіді

1. Що рефакторю і чому саме це.
2. Вивід `npm test` до.
3. Діф (лише продакшн-код).
4. Вивід `npm test` і `typecheck` після + `git diff --name-only`.
5. Порівняння результатів на 3 входах до/після.
6. «Не чіпав, але варто».

## Stop

Після зелених тестів зупинись. Не бери другий пункт зі свого ж списку «варто» —
це наступна ітерація й окреме рев'ю.

## Результат запуску

**Коли:** 2026-09-14 · **Ціль:** розподіл остачі у `splitInstallments`

**1. Що рефакторив і чому.** Після виправлення дефекту (`debug-failing-test.md`)
розподіл остачі виглядав так:

```ts
let remainder = totalCents - base * parts;
const step = remainder < 0 ? -1 : 1;
for (let i = 0; remainder !== 0; i += 1, remainder -= step) {
  result[i] += step;
}
```

Код правильний, але читач мусить у голові симулювати цикл із **двома**
лічильниками, що змінюються одночасно (`i` вгору, `remainder` до нуля), щоб
переконатись, що не буде виходу за межі масиву. Це найдорожчий рядок у файлі
за ціною «секунд на розуміння».

**2. `npm test` до:** `Tests 23 passed (23)`.

**3. Зміна.** Мутуючий цикл → декларативний `Array.from`, де умова стала
самоописовою:

```ts
const remainder = totalCents - base * parts;   // знак збігається зі знаком суми
const step = Math.sign(remainder);
const extra = Math.abs(remainder);             // завжди < parts

return Array.from({ length: parts }, (_, i) => (i < extra ? base + step : base));
```

Читається як речення: «перші `extra` платежів більші на один крок». Гарантія
меж тепер видима з типу виразу (`i < extra`, `extra < parts`), а не виводиться
з поведінки циклу.

**4. `npm test` після:** `Tests 23 passed (23)`, `tsc --noEmit` чисто.

**Тут промпт спіткнувся об власний критерій — і це найкорисніше, що дав цей
прогін.** Критерій v1 казав: «файл тестів не в дифі, `git diff --name-only` це
підтверджує». Виконую — і отримую:

```
app/package-lock.json
app/src/quote.test.ts
app/src/quote.ts
```

Тобто критерій «провалився», хоч рефакторинг був бездоганний. Причина: голий
`git diff` показує зміни проти **бази гілки**, а там уже лежали тести з
`add-tests.md` і виправлення з `debug-failing-test.md`. Критерій вимірював не
те, що мав.

Два висновки, обидва пішли у правки:

- **Критерій уточнено** (див. acceptance criteria вище): діф треба брати від
  стану *безпосередньо перед рефакторингом* — чекпойнт-коміт або
  `git diff <sha> -- app/src/`. Скопом узятий діф гілки для цього не годиться.
- **`app/package-lock.json` теж виявився в дифі** — і це взагалі не мій
  рефакторинг: локфайл перегенерувався іншою версією npm (зникли поля `libc`
  у платформених залежностях `rolldown`). Відкотив: `git checkout -- app/package-lock.json`.
  Без цього критерію шум поїхав би в PR непоміченим.

Після уточнення критерію діф саме цього рефакторингу — рівно один файл,
`app/src/quote.ts`.

**5. Звірка на трьох входах (фактичний вивід до і після):**

| Вхід | До | Після |
|---|---|---|
| `splitInstallments(10000, 3)` | `[3334,3333,3333]` | `[3334,3333,3333]` |
| `splitInstallments(90000, 3)` (ділиться націло) | `[30000,30000,30000]` | `[30000,30000,30000]` |
| `splitInstallments(-10000, 3)` (сторно) | `[-3334,-3333,-3333]` | `[-3334,-3333,-3333]` |

**6. Не чіпав, але варто:**

- `formatMoney` мовчки ламається на дробових центах: `formatMoney(10.5)` дає
  `"$0.5"` замість помилки. Це **зміна поведінки**, отже не рефакторинг —
  окрема задача з рішенням продукту.
- Три `RangeError`-гарди дублюють структуру повідомлення. Витягти в хелпер
  можна, але тексти задокументовані в `app/README.md`; ризик розсинхрону
  більший за виграш на трьох рядках.

**Що спрацювало в промпті.** Критерій «файл тестів не змінювався цим
рефакторингом» — єдиний тут, який неможливо виконати «приблизно»: він
перетворює «я нічого не зламав» із наміру на перевірюваний факт, бо тест,
який довелося торкнути, за визначенням означає зміну поведінки.

Але — див. пункт 4 — важлива не сама ідея критерію, а **точність команди в
ньому**. Формулювання «`git diff --name-only` це підтверджує» звучало
перевірюваним, а насправді вимірювало діф усієї гілки. Перевірюваний критерій
із неправильною командою гірший за відсутній: він дає хибну впевненість і його
хочеться просто проігнорувати, коли він «неправильно» червоний. Урок на всю
бібліотеку: у критерій пишемо не «переконайся дифом», а точну команду з точною
базою порівняння.

**Що спрацювало гірше.** Обмеження «один рефакторинг за раз» довелось
застосувати до себе силою: спокуса заодно витягти гарди в хелпер була сильною,
і саме її зупинив пункт 6 — замість правки вона стала записом у списку.
