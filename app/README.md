# `quote` — розрахунок кошторису

Модуль рахує вартість проєкту автоматизації, розбиває її на платежі й форматує
суми для документів. Усі суми — **цілі числа в центах**; float тут не
використовується ніде, щоб на розбитті не втрачались копійки.

Джерело: [`src/quote.ts`](./src/quote.ts). Тести: `npm test` (потрібен Node 22+).

## API

| Експорт | Сигнатура | Що робить |
|---|---|---|
| `QuoteInput` | `{ hours: number; rateCents: number; discountPercent?: number }` | Вхід для розрахунку. `rateCents` — ставка за годину **в центах** (`5000` = $50.00). `discountPercent` — 0..100, за замовчуванням `0`. |
| `estimateTotalCents` | `(input: QuoteInput) => number` | Вартість у центах із урахуванням знижки, округлена до цілих центів. |
| `splitInstallments` | `(totalCents: number, parts: number) => number[]` | Розбиває суму на `parts` платежів. Довжина результату завжди дорівнює `parts`. |
| `formatMoney` | `(cents: number) => string` | Форматує центи як `"$1,234.50"`. Знак мінус ставиться **перед** символом валюти: `"-$12.34"`. |

### Коли кидає помилку

| Виклик | Помилка |
|---|---|
| `estimateTotalCents` з `discountPercent` поза `0..100` (або `NaN`/`Infinity`) | `RangeError: discountPercent має бути в межах 0..100, отримано 150` |
| `splitInstallments` з `parts`, що не є цілим ≥ 1 (`0`, `-1`, `2.5`) | `RangeError: parts має бути цілим числом ≥ 1, отримано 0` |
| `splitInstallments` з дробовим `totalCents` | `RangeError: totalCents має бути цілим числом центів, отримано 10.5` |

Інших перевірок входу немає — див. «Відомі обмеження».

## Приклад

```ts
import { estimateTotalCents, splitInstallments, formatMoney } from "./src/quote.js";

// 20 годин × $50.00
const total = estimateTotalCents({ hours: 20, rateCents: 5000 });
// → 100000        formatMoney(total) === "$1,000.00"

// три платежі: 100000 не ділиться на 3 націло
const parts = splitInstallments(total, 3);
// → [33334, 33333, 33333]
// сума = 100000 — зайва копійка осіла в ПЕРШОМУ платежі, а не зникла

parts.map(formatMoney);
// → ["$333.34", "$333.33", "$333.33"]
```

Вивід звірено запуском на поточному коді, а не написано з голови.

## Інваріанти

1. **Усі суми — цілі числа в центах.** Долари в модуль не передаються ніколи;
   `formatMoney` — єдине місце, де центи стають доларами, і лише для показу.
2. **`splitInstallments` не втрачає і не створює грошей.** Для будь-яких
   допустимих входів `sum(splitInstallments(t, n)) === t`. Остача від ділення
   розподіляється по перших платежах, а не округлюється в кожному окремо.
   Для від'ємних сум (повернення коштів) інваріант той самий.

## Відомі обмеження

- **Валюта захардкожена.** `formatMoney` завжди друкує `$` і формат `en-US`.
  Параметра валюти чи локалі немає.
- **Від'ємні `hours` і `rateCents` не перевіряються.** `estimateTotalCents({ hours: -10, rateCents: 5000 })`
  поверне `-50000` без помилки. Це свідоме рішення — від'ємна сума може бути
  легітимним сторно; якщо у вашому сценарії це не так, валідуйте на рівні виклику.
- **Немає роботи з податками, авансами й графіком платежів у часі.**
  `splitInstallments` ділить суму, але нічого не знає про дати.
